## How it works

A small multi-cycle RISC-V CPU implementing the RV32E base integer instruction set
(RV32I instructions with 16 registers). FENCE, ECALL and EBREAK are treated as NOPs.

Program code is fetched from an external SPI flash and data lives in an external SPI RAM,
both on the Tiny Tapeout QSPI Pmod pins, used in plain 1-bit SPI mode
(READ `0x03` / WRITE `0x02`, 24-bit address, SPI mode 0, SCK = clk / 2).

Each instruction goes through three states: FETCH (read 4 bytes at PC over SPI),
EXEC (decode, ALU, register write-back, next PC) and, for loads and stores, MEM.

Memory map:

| Address range | Device |
|---|---|
| `0x0000_0000` - `0x00FF_FFFF` | SPI flash on CS0 (code, read only) |
| `0x0100_0000` - `0x01FF_FFFF` | SPI RAM on CS1 (data) |
| `0x0200_0000` | I/O: store writes the low byte to `uo_out`, load returns `ui_in` |

## How to test

Load a RISC-V RV32E program (little-endian, starting at address 0) into the flash,
then release reset. The program can show results on `uo_out` by storing a byte to `0x0200_0000`
and read the switches on `ui_in` by loading from the same address.

The test program in `test/program.hex` (generated by `test/make_hex.py`) checks every
integer instruction and writes `0x01` to `uo_out` on success or `0xFF` on failure.

## External hardware

QSPI Pmod (flash on CS0, RAM on CS1), or the RP2040 on the Tiny Tapeout demo board
emulating SPI flash and RAM.
